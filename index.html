How remuxing works

What it fixes

A file that won't seek, shows the wrong length, or gets rejected by an editor or an older player. It rebuilds the packaging, not the media.

How it works

The encoded audio and video are copied into a fresh container. Nothing is re-encoded, so the quality is identical to the original.

Where it runs

In this tab, on your device. No upload, no queue, no account — and no server to wait on.

What remuxing can and can't do

Think of it like a box. The container (MP4, WebM) is the box; the codecs inside (H.264, AAC, VP9) are the contents. Remuxing puts the same contents in a new box. Nothing inside is touched, so nothing gets worse.

It can move existing streams into a compatible container, rebuild the index so seeking works, and recalculate missing durations and timestamps.

It can't change codecs. If the target container won't accept a codec, that needs a re-encode, which this tool doesn't do — you get an explanation instead of a quietly degraded file. It also can't repair damaged frame data: if the media itself is corrupt, a new container won't save it.

Good to know — a file whose extension lies (a WebM named .mp4) is detected by its actual bytes, not its name. Your original file is never modified.

Subtitles

Pull the subtitle tracks out of a video as separate .srt files. Text tracks convert cleanly; image-based ones (PGS, VobSub) can't be turned into text without OCR. The .cc in the domain is for closed captions — this is that tool.
