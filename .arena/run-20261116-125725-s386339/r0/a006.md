# The hero lockup — two pastes

One block of HTML, one block of CSS, nothing else on the page touched.

---

## What is wrong with the version you have

Five questions I asked before drawing anything. Every answer is measured on the
page as it stands at 1440px.

**1. Does the mark read as a download?** The tray is one horizontal line
(`M4 19h16`), so the arrow is sitting on an underscore. The app's own downloads
button — 15px tall in the top bar — draws a proper tray with sides. The hero is
a bigger, cruder version of the same idea.

**2. Is it the page's weight?** `stroke-width="2"` in a 24-unit box renders at
3.7px in the 44px mark, heavier than the wordmark's ~3.3px stems. A mark has to
be a little *lighter* than the type beside it to look equal to it.

**3. Is the mark the size the type is?** Its box is 44px, but the drawing only
uses 18 of its 24 units: 33px of ink floating in 5.5px of dead space on every
side. So the optical gap to the word is about 20px, not the 14px written in the
CSS, and the lockup reads as "an icon, then a word".

**4. Is `mdown.cc` set as one name?** The dot is a 0.19em period glyph (7px)
dragged into the `n` with `-0.14em` of negative margin, and its shape is whatever
the font decides — a heavy square in Menlo, something else in the next font down
the stack. `cc` is 0.72em at weight 400 in `--text-3`: the definition of an
afterthought.

**5. Is the entrance one gesture?** Three things move: the whole lockup fades in
over 240ms on `--ease`, while the arrow drops 9px and the word drops 5.4px on a
second curve, the word starting 70ms late. And `fill-mode: both` leaves
`translate3d(0,0,0)` on "down" for the life of the page — it never rejoins the
"m", so the two halves can render a shade differently.

Each fix below answers one of those five.

---

## 1 · The markup

In `index.html`, replace the whole `<h1 class="hero-logo">` block (lines
304–315) with this:

```html
<h1 class="hero-logo">
      <span class="hero-mark" aria-hidden="true">
        <svg viewBox="4.2 2.2 15.6 18.8">
          <!-- the arrow is its own group so it can travel into the tray -->
          <g class="mark-arrow"><path d="M12 2.8V14"/><path d="m7.4 9.4 4.6 4.6 4.6-4.6"/></g>
          <path class="mark-tray" d="M4.8 14.6v3.2a2.6 2.6 0 0 0 2.6 2.6h9.2a2.6 2.6 0 0 0 2.6-2.6v-3.2"/>
        </svg>
      </span>
      <span class="hero-word"><span class="hero-word-m">m</span><span class="hero-word-down">down</span><span class="hero-word-dot">.</span><span class="hero-word-sub">cc</span></span>
      <span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

The `viewBox` is trimmed to the ink, so the SVG's box *is* the drawing and its
bottom edge is the underside of the tray. That is the whole trick that puts the
mark on the baseline. The arrow keeps its own group; the tray keeps its job.

## 2 · The CSS

In `assets/app.css`, replace the hero block — from `.hero { width: 100%; }` down
to `.hero-logo { margin-bottom: clamp(18px, 3vh, 28px); }` (≈ lines 2306–2381) —
with this:

```css
/* hero: the lockup --------------------------------------------------------
   One font-size drives the whole lockup — the name, the mark, the gap, the dot
   are all in em, so it scales as a single object and needs no second
   breakpoint. The mark is baseline-aligned: its tray rests on the same line as
   the feet of the letters. */
.hero { width: 100%; }

.hero-logo {
  display: flex;
  align-items: baseline;
  justify-content: center;
  gap: 0.32em;
  margin: 0 auto clamp(18px, 3vh, 28px);
  font-family: var(--mono);
  font-size: clamp(1.9rem, 5vw, 2.5rem);
  font-weight: 500;
  letter-spacing: -0.035em;
  line-height: 1;
  color: var(--text);
}

/* the mark: an arrow and the tray it lands in, drawn at one weight. The box is
   trimmed to the drawing, so its bottom edge is the tray's underside and the
   mark stands on the baseline instead of floating beside the word. */
.hero-mark {
  flex: none;
  padding-top: 0.17em;   /* the arrow's flight path, kept inside the lockup */
  color: var(--text);
}
.hero-mark svg {
  display: block;
  width: 0.93em;         /* 1.12 × 0.83: the viewBox's own ratio, so nothing is letterboxed */
  height: 1.12em;
  overflow: visible;     /* the arrow starts above its resting place */
  fill: none;
  stroke: currentColor;
  stroke-width: 1.15;    /* the drawing's units — 2.7px at the 2.5rem size */
  stroke-linecap: round;
  stroke-linejoin: round;
}

/* the name: one run of type, split only where it moves */
.hero-word { display: inline-block; }
.hero-word-m { display: inline; }
.hero-word-down { display: inline-block; }

/* the dot is the joint between the name and the tld, so it gets its own 0.15em
   slot instead of a whole 0.6em mono cell — that cell of air on both sides is
   what made the name and the tld look unrelated. It is drawn rather than typed:
   a period is a square in Menlo and a different shape in every other mono. */
.hero-word-dot {
  display: inline-block;
  position: relative;
  width: 0.15em;         /* the dot's own advance, not a whole 0.6em mono cell */
  height: 1em;           /* a box to hold it; a shorter one notches the selection */
  overflow: hidden;      /* its baseline is now its bottom edge, the type's baseline */
  margin: 0 0.065em;
  color: transparent;    /* the glyph is the text; the dot below is its ink */
}
.hero-word-dot::after {
  content: "";
  position: absolute;
  left: 50%;
  bottom: 0;             /* the baseline */
  width: 0.15em;
  height: 0.15em;
  margin-left: -0.075em;
  border-radius: 50%;
  background: var(--accent);
}

/* the tld: a step down in size and one in colour, on the same baseline */
.hero-word-sub {
  font-size: 0.8em;
  font-weight: 500;
  letter-spacing: 0;
  color: var(--text-2);
}

/* one gesture: the arrow drops into the tray and the half of the name it hangs
   over falls with it — same distance, same curve, same 760ms, no delay, no
   overshoot. The curve is the site's own (--ease), the one the mode switch
   rides. */
@keyframes hero-arrow-drop {
  from { transform: translateY(-2.7px); }   /* the drawing's units: 6.4px at 40px */
  to   { transform: translateY(0); }
}
@keyframes hero-word-drop {
  from { transform: translateY(-0.16em); }  /* the same 6.4px at 40px */
  to   { transform: translateY(0); }
}
.mark-arrow     { animation: hero-arrow-drop 760ms var(--ease) backwards; }
.hero-word-down { animation: hero-word-drop  760ms var(--ease) backwards; }

@media (prefers-reduced-motion: reduce) {
  .mark-arrow, .hero-word-down { animation: none; }
}
```

**Selectors it replaces:** `.hero`, `.hero-logo`, `.hero-mark`, `.hero-mark svg`,
`.hero-word`, `.hero-type`, `.hero-word-m`, `.hero-word-down`, `.hero-word-dot`,
`.hero-word-sub`, plus the keyframes `hero-fade-in`, `arrow-drop`, `word-drop`
(now `hero-arrow-drop`, `hero-word-drop`). `.hero-type` no longer exists in the
markup, so it is not carried over.

Three things moved house, so you know where to look: the size, family, weight and
tracking now sit on `.hero-logo` (one rule sizes the mark, the gap and the name
together, and the mark's `em` values hang off it); the two `.hero-logo` margin
rules are merged into one; and the old fade of the whole lockup is gone.

**Two rules that mention these classes and must stay exactly as they are:** the
short-window padding on `.hero` (`2vh`, line ≈ 1307) and `display: none` on
`.hero-logo` for landscape phones (line ≈ 3168).

## 3 · Why this, not the old one

(134 words)

The mark is now a tray with sides, so the arrow has somewhere to land, and it is
drawn at 2.7px against the word's 3.3px stems — an icon has to be slightly
lighter than text to read as equal. It is sized in em off the same font-size as
the name and sits on the baseline, so the tray rests on the line the letters
stand on at every width, and the optical gap to the word drops from ~20px to
~14px because the drawing now fills its box. The dot is a 0.15em circle in a
0.15em slot rather than a 7px square squeezed in with negative margin; `cc` is
0.8em in `--text-2` rather than 0.72em in `--text-3`. The entrance is one
motion: 6.4px, one curve, 760ms, no delay, nothing left transformed.

## 4 · What to look at

- **1440px** — reload once: the arrow and "down" land together in about
  three-quarters of a second; the tray's underside sits on the same line as the
  feet of `mdown`; the dot is a 6px circle that reads as a full stop, not a
  bullet, and it is close to both `n` and `c` without touching either.
- **360px** — the lockup is centred with roughly 80px of air each side, the tray
  is still on the baseline, `cc` still reads as two letters, and nothing wraps or
  clips.

What I checked before writing this: no horizontal overflow at 320, 360, 768 or
1440px; the tray's ink bottom lands 0px from the text baseline at 30.4px, 38.4px
and 40px type; the arrow's starting position stays inside the lockup's box, so
nothing outside it moves; the animation ends with `transform: none`, so no layer
is left behind; a font swap to Courier keeps the spacing intact (the dot is
drawn, so it cannot change shape); the `<h1>` still announces
"mdown.cc — a media downloader for video and audio" and the mark is still
`aria-hidden`.

## 5 · Assumptions

- **The wordmark stays real text.** The `.` is still a text node; only its ink is
  drawn. Copy, translation and screen readers still get `mdown.cc`, and under
  forced colours the glyph takes over again. If you would rather keep the typed
  period, delete the `.hero-word-dot` rules and use
  `.hero-word-dot { margin: 0 -0.1em }` — you will get a square on Menlo.
- **The name keeps its `m` + `down` split**, because only the second half
  animates. At rest the seam is invisible: no margin, no tracking change, no
  whitespace between the spans.
- **`cc` steps down in size and colour** (0.8em, `--text-2`) rather than taking a
  new token, so light theme needs no extra work.
- **The lockup's box is ~14px taller** than before — the mark is now a 45px
  drawing rather than 33px of ink inside a 44px box — so the field below starts
  14px lower. Its distance from the lockup is unchanged (~30px).
