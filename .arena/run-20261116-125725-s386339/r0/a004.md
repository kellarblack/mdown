# The hero lockup, drawn rather than assembled

Three changes, and the lockup stops looking like a glyph next to a word:

1. **The mark is redrawn as a hairline.** It was 2 units of stroke on a 24-unit grid shown in a 44 px
   box: 3.7 px of paint, twice the weight of every other line on the page. It is now 0.95 units —
   **1.8 px at 38 px type** — and it scales with the type instead of with its own `clamp()`.
2. **The mark's box is cropped to its ink**, so the box *is* the drawing: the bottom edge is the tray,
   the top edge is the arrow's cap. Alignment becomes measurement instead of a guess, and the tray
   sits on the wordmark's baseline at every width.
3. **The name is set once.** One tracking value across all eight characters, a `cc` that is the same
   size as the name (a domain, not a footnote) and only a step quieter in weight and tone.

Same type size, same mark geometry as the header brand, same margin to the composer.

## Why this, not the old one

The old mark was 2 units of stroke in a 24-unit drawing at 44 px: 3.7 px of paint, twice the weight of
everything else on the page. It is now 0.95 units in a box cropped to its ink — 1.8 px, a hairline that
scales with the type.
That crop also fixes the seating: the box's bottom edge is the tray, so it lands on the baseline
exactly, instead of wherever two clamps happened to agree.
The old drop was half off-screen: the arrow started 11 px above a box with `overflow: hidden`. It now
starts in its own air.
And the name is set once: one tracking value for eight characters, not an `m`/`down` margin, a −0.14em
dot and a zero-tracked `cc` fighting in seven. `cc` stays the full size, a step quieter in weight and
tone — a domain, not a footnote.

## Check it

**At 1440 px:** the tray bar sits on the `m`'s baseline (put an underline on *mdown* and it collides),
the arrow's cap clears the `d` by about 3 px, and `mdown` is white while `cc` is one step quieter.
**At 360 px:** the mark-to-word gap tightens with the type instead of staying 14 px wide, `mdown.cc`
holds one line with room on both sides, and the stroke is still a hairline — nothing clips.

## Assumptions

- **`.cc` is part of the name**, so it is set at the name's size and separated by tone, not by shrinking.
  If you would rather it read as a suffix, `font-size: 0.86em` on `.hero-word-sub` is the only change needed.
- **The mark keeps the header's geometry.** Only its stroke, its crop and its seating changed, so the
  hero and the top bar are the same logo at two sizes (1.8 px and 1.25 px of stroke — both hairlines).
- **The accent dot keeps `var(--accent)`**, which is identical to `--text` today, so no colour is added.
- **The lockup's box is ~5 px shorter** than before (44 px → 38.7 px at 1440). The column is vertically
  centred, so the hero's box shifts about 3 px while the ink stays put — the word's baseline moves
  0.1 px. Nothing else on the page is touched.
- **The accessible name is unchanged**: `mdown.cc — a media downloader for video and audio`, mark still
  `aria-hidden`. No JS, no images, no new colours — `--accent` on the dot is still `--text`.

## Measured, so you can check it without guessing

Rendered in Chrome at 1440 × 900 and in a 320 px viewport with the blocks above pasted in:

- stroke **1.80 px** at 1440, **1.31 px** at 320 — it scales with the type, as a logo should
- tray bottom to the `m`'s baseline: **0.00 px** at 1440, 500 and 320 px. That is `align-items: baseline`
  using the SVG box's bottom edge, which is the spec's baseline for an element that has none: no magic
  offset anywhere, so nothing to drift
- mark top to the `d`'s ascender: **+3.1 px** at 1440, +2.2 px at 320
- lockup width **206 px** at 1440, **151 px** at 320 inside 288 px of column — one line, nothing clipped
- the gap is `0.34em` because that is the shipped 14 px gap at 38 px type: the desktop composition is
  untouched, the gap just scales now (9.5 px at 360) instead of staying 14 px on a 28 px lockup
- arrow travel **5.18 px**, `down` travel **5.18 px** — both 0.135em, both 600 ms, one start
- the arrow's first frame reaches ~5 px above the lockup's box, into the column's 24–44 px top padding;
  nothing else is within 20 px of it, and it is gone in under a second
- reduced motion: no animation at all, final position, nothing to un-do
