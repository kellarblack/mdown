## 2. `assets/app.css` — replace lines 2301–2369

That block starts at `.hero { width: 100%; }`, right after the `#download-view` rule, and ends at
`.hero-logo { margin-bottom: clamp(18px, 3vh, 28px); }`, just above `.meta-line`. It holds `.hero`,

`.hero-word-down`, `.hero-word-dot`, `.hero-word-sub`, `.mark-arrow`, and the keyframes
`hero-fade-in`, `arrow-drop`, `word-drop`.

```css
.hero { width: 100%; }

/* one size drives the whole lockup: the mark is a 1em square and the word
   inherits the same em, so the arrow's top lands on the ascender height and
   the tray lands on the baseline at every viewport width, with no nudges. */
.hero-logo {
  display: flex; align-items: center; justify-content: center;
  gap: 0.21em;
  font-size: clamp(1.7rem, 4.6vw, 2.9rem);
  line-height: 1;
  margin: 0 auto clamp(18px, 3vh, 28px);
  color: var(--text);
}

/* the top bar's drawing at hero size, with the 1.7 stroke the social card
   uses: at this size that is the weight of the letter stems, so the mark
   belongs to the word instead of standing beside it. the drawing fills the
   middle 0.74em of its square, so the negative margin gives that empty air
   back — the gap below is the gap you see, and the ink stays centred. */
.hero-mark { flex: none; width: 1em; height: 1em; margin-inline: -0.07em; }
.hero-mark svg { display: block; width: 100%; height: 100%; }

/* mdown.cc: the name at full size, the dot and the tld one step down and one
   step back. a monospace period is a whole cell wide, so the dot's side
   bearings are handed back — otherwise it floats like a bullet between the
   name and the tld instead of joining them. */
.hero-word {
  font-family: var(--mono); font-weight: 500;
  letter-spacing: -0.02em; white-space: nowrap;
}
.hero-dot, .hero-tld { font-size: 0.72em; font-weight: 400; letter-spacing: 0; }
.hero-dot { color: var(--text-2); margin: 0 -0.21em 0 -0.14em; }
.hero-tld { color: var(--text-3); }

/* one object moves: the arrow drops the last 4 of the mark's 24 units into
   the tray, on the site's curve. the name never moves and nothing fades, so
   the lockup is fully legible even if the animation never runs. */
.mark-arrow { animation: mark-drop 760ms var(--ease) both; }
@keyframes mark-drop {
  from { transform: translate3d(0, -4px, 0); }
  to   { transform: translate3d(0, 0, 0); }
}
@media (prefers-reduced-motion: reduce) {
  .mark-arrow { animation: none; }
}
```

## Why this, not the old one

The old lockup failed on things you can measure.

The arrow was drawn at stroke 2 but boxed at up to 44px, so it rendered up to 3.7px — heavier than
the letter stems beside it. The name was in three voices: white `mdown`, a full-size white period, a
0.72em grey `cc`, plus a `margin-left: 0.05em` that opened a visible `m down` seam. And a monospace
period is a whole cell wide, so the dot floated like a bullet between two words. On top of that,
three animations ran on three clocks: a 240ms fade, a 760ms arrow, an 830ms word.

Now one 1em box drives the mark and the type, the stroke thickens with the type, the period's air is
handed back so `.cc` reads as a suffix, and one object moves.

## What to look at

**1440px:** the arrow's top should sit on the top of the `d` and the tray on the letters' baseline;
the period should look closer to the `cc` than to the `n`, so it reads as `mdown.cc` and not
`mdown . cc`. Nothing should sit lower or higher than the word by eye.

**360px:** one line, about 150px wide, centred over the paste field — the mark's stroke weighing the
same as the letter stems, no second line, nothing clipped at either edge.

Reload once to see the entrance: the arrow comes down into the tray in about 0.76s and nothing else
moves or fades.

## So you can tune it

- mark box `1em` → arrow top on the ascender, tray on the baseline (0.8px above it at 46.4px type)
- stroke `1.7` of 24 units → 3.3px at 1440, 1.9px at 360: it stays the same weight *relative to the
  type*, instead of being a fixed hairline next to much larger letters
- visible gap `0.27em` (≈12.6px at 1440) = the `0.21em` gap minus `0.07em` of empty air inside the
  mark's square, handed back on both sides
- `.cc` at `0.72em`; the period pulled in by `-0.14em` / `-0.21em` so it joins the tld
- word `46.4px` max / `27.2px` floor; `-0.02em` tracking, the same value the top bar uses
- one animation: `mark-drop`, `760ms`, `--ease`, 4 of the mark's 24 units

## Assumptions

- The hero should be the same lockup as the mark in the top bar and the one on the social card, at
  hero size. That is where the 1.7 stroke and the 0.72em `cc` come from: the page already has this
  lockup at two sizes, and the hero was the only one built differently.
- `.cc` is a domain suffix, not the end of the name, so it is one step smaller and one grey step
  back — `--text-2` for the dot, `--text-3` for the `cc`, the same two roles the top bar uses.
- The arrow is the only thing that moves. I did not split the name so that `down` falls with it:
  that is the one part of the old build I removed on purpose, because half a word falling is what
  keeps reading as choreography. It is one span and one keyframe to put back; I would not ship it.
- The screen-reader sentence in the `<h1>` stays. It is invisible and it is the only description the
  name has.

## Held to the brief

- plain HTML and CSS in these two files: no images, no SVG files, no webfonts, no JS
- monochrome: five existing custom properties, no new colour, no glow, no gradient, no shadow
- motion: transform only, one shot, `--ease`, 760ms, no overshoot, `animation: none` under
  `prefers-reduced-motion: reduce`
- 320px–1440px: measured zero horizontal overflow at 320, 360 and 390; the landscape-phone rule
  still hides the lockup because the class is still `.hero-logo`
- semantics kept: `<h1>`, the wordmark is real text, the mark is `aria-hidden`
- nothing else on the page was touched: composer, top bar and footer are as they were
