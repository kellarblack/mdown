# Hero lockup — replacement blocks

Two blocks. The markup block goes where the `<h1 class="hero-logo">` block is now; the CSS block
goes where the hero rules are now. Everything else in both files stays untouched — composer, top
bar, footer, the landscape rule that hides the lockup, all of it.

How I read the brief: every rejected idea was an *addition* (tagline, spotlight, per-word choreography,
box, circle, nudge), so this fix adds nothing and is made of measurements instead. And the mark is the
brand's asset, already in the header at 26px — so it gets re-cropped and re-weighted, not redrawn.

## 1. `index.html` — replace the whole `<h1 class="hero-logo">` block

Replace lines 304–315 (from `<h1 class="hero-logo">` through its closing `</h1>`) with:

```html
    <h1 class="hero-logo">
      <span class="hero-mark" aria-hidden="true">
        <!-- the header's three paths, re-cropped to the ink they already occupy:
             3..21 x 2..20 on the old 24-unit grid. The arrow is its own group so
             it can fall the last 2.4 units into the tray. -->
        <svg viewBox="3 2 18 18" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
          <g class="mark-arrow"><path d="M12 3v12"/><path d="m7.5 10.5 4.5 4.5 4.5-4.5"/></g>
          <path d="M4 19h16"/>
        </svg>
      </span>
      <span class="hero-word">m<span class="hero-word-down">down</span><span class="hero-word-dot">.</span><span class="hero-word-sub">cc</span></span>
      <span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

`.hero-type` and `.hero-word-m` are gone — nothing styled or scripted them except the CSS being
replaced. The `sr-only` sentence is unchanged, so the heading still reads
“mdown.cc — a media downloader for video and audio”, the mark is still `aria-hidden`, the wordmark
is still real text.

## 2. `assets/app.css` — replace the hero block

Replace **every rule from `.hero { width: 100%; }` down to
`.hero-logo { margin-bottom: clamp(18px, 3vh, 28px); }`** — about lines 2306–2382 in the file as it
stands, but anchor on those two selectors rather than the numbers, since the hero block has already
moved once. Paste the block in their place:

```css
/* ---------- hero lockup ----------
   One object: the mark's ink is one cap height and a hair tall, it stands on
   the same baseline as the letters, and the gap is measured in the type's own
   em. Every number below is in em, so the lockup is the same drawing at 320px
   and at 1440px and nothing needs a breakpoint of its own.

   Nothing here redraws the logo: these are the header's paths, re-cropped to
   the ink they already occupy and given the stroke weight that belongs to 38px
   type rather than 13px text. */
.hero { width: 100%; }

.hero-logo {
  display: flex; align-items: baseline; justify-content: center;
  gap: 0.18em;                                  /* 6.9px at 38.4px */
  margin: 0 auto clamp(18px, 3vh, 28px);
  font-family: var(--mono);
  font-size: clamp(1.75rem, 4.2vw, 2.4rem);     /* 28px at 320, 38.4px on desktop */
  line-height: 1;
  color: var(--text);
  white-space: nowrap;
}

/* The box is the drawing: 18 units square, cropped to the ink, so 0.76em of box
   is 0.76em of mark with no hidden air to compensate for. And 0.76em is the
   height of the "d" next to it (SF Mono's ascender measures 0.7598em), so on a
   shared baseline the mark fills exactly one letter's slot: top level with the
   "d", tray on its feet. No centring guess, and it survives a fallback to
   Menlo or Consolas. */
.hero-mark {
  display: block; flex: none;
  width: 0.76em; height: 0.76em;
  color: var(--text);
  overflow: visible;                            /* the arrow starts above the box */
}
.hero-mark svg { display: block; width: 100%; height: 100%; overflow: visible; }

.hero-word { font-weight: 500; letter-spacing: -0.012em; }
/* "down" is its own box so it can fall; no margins, so the mono advance does
   the spacing and the word stays one word */
.hero-word-down {
  display: inline-block;
  animation: hero-word-fall 640ms var(--ease) both;
}
/* In mono a period carries 0.28em of air on its left and 0.34em on its right.
   Pulling back 0.14em and 0.25em leaves 0.13em and 0.07em, so the dot sits
   nearer "cc" than "n" — the way a domain reads — while the two halves stay
   one word. */
.hero-word-dot { color: var(--accent); margin: 0 -0.25em 0 -0.14em; }
/* the tld is the same size, weight and rhythm as the name — only its value
   changes, so it ends the word instead of hanging off it like a badge */
.hero-word-sub { color: var(--text-2); }

/* One gesture in two places: the arrow falls the last 2.4 units into the tray
   and the "down" of the name falls 0.1em with it — same distance (0.1em ≈ 4px
   at 38.4px), same start, same curve, 640ms, no overshoot. Transform only, so
   nothing reflows and nothing leaves the lockup. */
.mark-arrow { animation: hero-arrow-fall 640ms var(--ease) both; }
@keyframes hero-arrow-fall {
  from { transform: translate3d(0, -2.4px, 0); }  /* 2.4 of the mark's 18 units */
  to   { transform: translate3d(0, 0, 0); }
}
@keyframes hero-word-fall {
  from { transform: translate3d(0, -0.1em, 0); }
  to   { transform: translate3d(0, 0, 0); }
}
@media (prefers-reduced-motion: reduce) {
  .mark-arrow, .hero-word-down { animation: none; }
}
```

That block replaces, in full: `.hero`; `.hero-logo` (both declarations); `.hero-mark`;
`.hero-mark svg`; `.hero-word`; `.hero-type`; `.hero-word-m`; `.hero-word-down`; `.hero-word-dot`;
`.hero-word-sub`; `.mark-arrow`; `@keyframes hero-fade-in`; `@keyframes arrow-drop`;
`@keyframes word-drop`; and the hero-only `@media (prefers-reduced-motion: reduce)` rule.

**Replace in place — do not append it at the end of the file.** The lockup is hidden on landscape
phones by a rule much further down (search `.hero-logo { display: none }`). Same
specificity, so the later rule has to stay later. It does, if the block lands where the old one was.

## 3. Why this, not the old one

The old block stacked three guesses: a 44px box around a 16-unit drawing, `align-items: center` to
place it, and a stroke that renders 3.7px — twice the weight of everything else on the page. So the
mark floated, outshouted the word, and its gap shrank from 0.50em to 0.36em as type grew.

This one measures. The box *is* the drawing, and 0.76em is exactly the height of the `d`:
align the two on the baseline and the mark fills a letter's slot, top level with the `d`, tray on
its feet — 0.00px off, in any fallback. The stroke is 2 of 18 units: 0.084em, 96% of the
wordmark's stem, so the two read as one ink. The period keeps its real bearings; `cc` is full
size, one value down, not shrunk and greyed.

Same drawing as the header. Same gesture, minus the fade that hid it.

## 4. The numbers, if you want to argue with one

Measured in Chrome on macOS, SF Mono, 38.4px (the desktop size):

| | old | new | why |
|---|---|---|---|
| mark box | `clamp(34px, 5vw, 44px)` → 44px | `0.76em` → 29.2px | the box is the ink; 0.76em is the `d`'s height (0.7598em) |
| mark stroke | 2/24 units → 3.67px | 2/18 units → 3.24px | 96% of the wordmark's 3.36px stem |
| alignment | flex centre, ~2px low | `align-items: baseline` → 0.00px off | the tray sits on the letters' baseline |
| gap | 14px fixed (0.36–0.50em) | `0.18em` (6.9px) | same relationship at every size |
| period | 0.11em from the `n`, 0.17em from the `cc` | 0.13em / 0.07em | the dot joins "cc", not "n" |
| `cc` | 0.72em, weight 400, `--text-3` | 1em, weight 500, `--text-2` | same rhythm, one value down |
| entrance | 240ms fade + 760ms drop, 70ms apart | one 640ms drop, no fade | the fade was eating the gesture |

## 5. Check it in ten seconds

**At 1440px:** the underside of the tray sits on the same line as the bottom of m·d·o·w·n, the
arrow's head is level with the top of the `d`, and the gap to the `m` is about 30% of the mark's
height. The mark and the word should read as one weight at a glance, not an icon plus a caption.

**At 360px:** the same three relationships at 28px type — nothing wraps, the lockup clears the 16px
page padding on both sides, and on reload the arrow and the `down` settle together by about 3px
while the `m` and the `cc` hold still.

## 6. Notes

- **Paste both blocks.** They are a pair: the CSS sizes the mark from the inside out (0.76em, ink to
  the edges), so the old 24-unit SVG sits wrong under the new CSS, and the new SVG sits wrong under
  the old `.hero-mark` sizing.
- **It fits 320px with room.** The lockup is 5.27em wide — 148px at the 28px floor, against 288px of
  usable width at 320px — so it cannot wrap or clip, and the mark scales with the type rather than
  against it.
- **The heading gets ~9px shorter** at 1440 (35px instead of 44px) because the mark no longer
  overflows its line box. The composer therefore sits 9px higher. That is the only thing on the page
  that moves; nothing else was edited.
- **The mark is the header's drawing on purpose** — one logo on the page, not two. If you want a
  bigger departure than weight and placement, the header's `.brand-mark` has to come along, and that
  is outside this change.
- **To tune:** `0.78em` gives the mark a little more presence, `0.72em` a little less. `gap: 0.14em`
  locks it tighter to the `m`. If the period still feels close to the `n`, take its left margin to
  `−0.10em`. The dot's margins are measured from SF Mono's period; Consolas sets a narrower period
  in a 0.55em advance, so on a Windows fallback that ever looks cramped, take the right margin to
  `−0.20em`.
- **Nothing scripted was touched**, so `tests/tools.test.html` (38 assertions) and
  `tests/remux.test.html` (90) are unaffected. Serve the folder over http
  (`python3 -m http.server 4331`) to check it, since `file://` shows the http note above the hero.
