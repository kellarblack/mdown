# The hero lockup

The mark was drawn at logo size with icon values, so it failed in four
measurable ways rather than in taste:

- **Weight.** `stroke-width="2"` in a 24-unit viewBox rendered at 44px is a
  **3.7px** stroke. The rest of the page's icons are 1.6–1.8 in the same
  24-unit box but render at ~18px, i.e. **1.2–1.3px**. The logo was the
  heaviest line on the page — it read as a bolder, different icon.
- **Alignment.** `align-items: center` centres a flex item on the *line box*,
  not on the letters. So the mark's ink was **10% taller than the ascender**
  and its tray hung **1.9px below** the bottom of the letters: mathematically
  centred, visibly sinking.
- **Distance.** The mark sat **23px** (0.60em — nearly a whole character cell)
  from the `m`. Two objects side by side, not one lockup.
- **The leftovers.** `cc` at `0.72em` in `--text-3` read as a version suffix
  rather than as the domain; the dot was never kerned — it was pulled and
  nudged by hand (negative margins, then a smaller size and a `vertical-align`
  nudge) while `--accent` stayed equal to `--text`, so the "accent dot" could
  never show at all; and the parts were held apart by margins that had nothing
  to do with the type.

Replace that with a mark that is *part of the type*: drawn in the lockup's own
em, standing on the same baseline, at the same optical weight, with the name
set as one run and the period kerned.

---

## 1. `index.html` — replace the `<h1 class="hero-logo">` block

It is the block that runs from `<h1 class="hero-logo">` to `</h1>` — lines
304–315 today. Replace all of it with:

```html
    <h1 class="hero-logo">
      <span class="hero-mark" aria-hidden="true">
        <svg viewBox="0 0 24 21.175" fill="none" stroke="currentColor" stroke-width="1.15"
             stroke-linecap="round" stroke-linejoin="round">
          <!-- the tray-and-arrow is the same geometry as the downloads button in
               the dock, so the page has one download glyph instead of two; the
               arrow is its own group so it can travel into the tray -->
          <g class="mark-arrow"><path d="M12 4.2v10.2"/><path d="m7.9 10.3 4.1 4.1 4.1-4.1"/></g>
          <path class="mark-tray" d="M5 17.6V19a1.6 1.6 0 0 0 1.6 1.6h10.8A1.6 1.6 0 0 0 19 19v-1.4"/>
        </svg>
      </span>
      <span class="hero-word">m<span class="hero-word-down">down</span><span class="hero-word-dot">.</span>cc</span>
      <span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

The `hero-type`, `hero-word-m` and `hero-word-sub` spans are gone: `cc` is now
ordinary text in the same voice, and the `.` keeps its own span only because it
needs to be kerned.

## 2. `assets/app.css` — replace the hero block

Everything from `.hero { width: 100%; }` down to the last
`.hero-logo { margin-bottom: … }` — lines 2306–2382 today. The selectors it
supersedes are listed in the block's first comment, so the paste is
self-documenting.

```css
/* ---------- hero lockup -----------------------------------------------------
   Replaces the whole hero block — from `.hero { width: 100%; }` through the
   old `.hero-logo { margin-bottom: … }`: .hero, .hero-logo (both rules),
   .hero-mark, .hero-mark svg, .mark-arrow + @keyframes arrow-drop, .hero-word,
   .hero-type, .hero-word-m, .hero-word-down + @keyframes word-drop,
   @keyframes hero-fade-in, .hero-word-dot, .hero-word-sub, and the
   prefers-reduced-motion rule.

   The mark is drawn as part of the wordmark, not set beside it: the foot of
   its tray lands on the text baseline, its ink is the height of the ascender
   in "down", its stroke is proportionally thinner than the page's icons, and
   every dimension is an em of the lockup's own type size — so the two cannot
   drift apart at any width, and there is nothing to re-tune per breakpoint. */
.hero { width: 100%; }

.hero-logo {
  display: flex;
  align-items: baseline;      /* the mark's foot lands on the text baseline */
  justify-content: center;
  gap: 0;                     /* the mark's own box carries its side air */
  margin: 0 auto clamp(18px, 3vh, 28px);
  font-family: var(--mono);
  font-size: clamp(1.75rem, 4.3vw, 2.6rem);
  font-weight: 500;
  line-height: 1;
  letter-spacing: -0.02em;
  color: var(--text);
  white-space: nowrap;
}

/* 24 × 21.175, with the tray's ink ending exactly on the bottom edge of the
   box: flex baseline alignment then puts that edge on the line the letters
   stand on. 1.06em makes the ink exactly as tall as the ascender. */
.hero-mark {
  flex: none;
  display: block;
  line-height: 0;
  width: 1.06em;
  color: var(--text);
}
.hero-mark svg { display: block; width: 100%; height: auto; }

/* The name needs no rule of its own: size, tracking and colour are the
   lockup's, so "mdown.cc" is one run of type instead of three fragments.
   Only the part that moves and the period that must be kerned get a hook. */

/* The period is kerned, not left in its cell: monospace puts about 0.24em of
   air on each side of it, which is what makes the name read as "mdown . cc".
   These two values close that air to the gap between any two letters; the
   right one is 0.06em deeper because a period's ink sits left of centre in
   its cell. The accent token stays on, so the dot still follows it. */
.hero-word-dot {
  color: var(--accent);
  margin-left: -0.12em;
  margin-right: -0.18em;
}

/* One gesture in two parts: the arrow drops into the tray and the second half
   of the name falls with it. Same curve, same duration, same start, and the
   same distance — 2.6 units of the mark and 0.115em of the type are the same
   0.115em, so they stay paired at every size. Transform only, one shot, no
   overshoot, and both parts remain inside the lockup's box throughout. */
.hero-word-down {
  display: inline-block;
  animation: word-drop 760ms var(--ease) both;
}

.mark-arrow { animation: mark-drop 760ms var(--ease) both; }

@keyframes mark-drop {
  from { transform: translateY(-2.6px); }    /* 2.6 user units = 0.115em */
  to   { transform: translateY(0); }
}
@keyframes word-drop {
  from { transform: translateY(-0.115em); }
  to   { transform: translateY(0); }
}

/* nobody asked for motion: show the lockup and be done */
@media (prefers-reduced-motion: reduce) {
  .mark-arrow, .hero-word-down { animation: none; }
}
```

Nothing else in either file changes. The landscape-phone rule further down
`app.css` (`.hero-logo { display: none; }` inside the
`(orientation: landscape) and (max-height: 500px)` query, line 3168 today) still
wins, because it comes after this block.

## Why this, not the old one

The old mark was a logo drawn with icon values, and it showed in numbers: a
3.7px stroke against the page's 1.2px icons, ink 10% taller than the ascender,
a tray hanging 1.9px below the letters' feet, and 23px of air, a whole
character cell, between mark and name. That is why it read as a sticker. This
version changes the numbers, not the idea: the mark is the dock's own download
glyph, sized from the type, standing on the baseline, at a stroke
proportionally lighter than any icon; the gap is a quarter of an em instead of
six tenths. The name is set in one voice with the period kerned, so `mdown.cc`
reads as a word rather than `mdown` plus a footnote. The entrance you liked is
kept, exactly paired.

## Check it in two places

**At 1440px:** hold a straight edge along the bottoms of `mdown` — the tray of
the mark stands on the same line, its top is level with the `d`, and the whole
lockup is ~217px of ink, centred over the composer with about 10px between mark
and `m`. Nothing looks bolder than the type.

**At 360px:** the same relationships hold with no re-tuning — one line, ~146px
wide inside the 328px column, the mark's stroke thinned to ~1.4px, the dot
still tight to the `n` and the `cc`; no wrap, no clipping. Reload to see the
arrow and `down` settle together once in 760ms; turn on Reduce Motion and
nothing moves.

## Assumptions

1. **Replace, don't patch.** The three old spans and their rules are deleted,
   not left in place — leaving them would leave dead hooks for the next person.
2. **The `sr-only` line is kept verbatim**, so the heading still announces
   "mdown.cc — a media downloader for video and audio".
3. **The single accent dot is the period in the name.** `--accent` currently
   equals `--text`, so the dot is separated by kerning, not colour; the token
   stays on the rule so it follows the accent if that ever becomes a colour.
4. **Measurements are in SF Mono** (first in the `--mono` stack) at 41.6px
   desktop and 28px mobile. Everything is em-based, so under Menlo or Consolas
   the same relationships hold to within about a pixel.
5. **The type size is allowed to change** (`4.3vw`, max `2.6rem`, from the
   previous `4.2vw` / `2.4rem`) — that is the one deliberate change outside the
   mark, and the clamp is the only number to touch if you want it bigger.
6. **Both blocks are anchored by their first and last line of content**, so a
   line that has shifted since this was written cannot send you to the wrong
   place.

## Hard requirements, ticked off

| Requirement | How |
| --- | --- |
| Plain HTML + CSS only | One inline `<svg>`; no files, images, webfonts or JS added |
| Monochrome | `--text`, `--accent`, `--mono`, `--ease` only; no gradient, glow or coloured shadow |
| Animation | `transform` only; one iteration; 760ms on `--ease`; no overshoot; the 4.8px travel is less than the ~7px of air above the ink, so nothing leaves the lockup at any frame; `animation: none` under `prefers-reduced-motion: reduce` |
| 320 → 1440px, no wrap or clip | Checked at 320/360/768/1024/1440: one line everywhere, `scrollWidth === clientWidth` at each width |
| Landscape phones still hide it | Untouched media query still wins by source order (checked at 900×420) |
| Semantics kept | `<h1>` stays, wordmark is real text, mark stays `aria-hidden` |
| Nothing else disturbed | Composer, top bar and footer untouched; the heading's box changes by 1px at desktop (44 → 45) and 3px on a phone, so the composer sits within 3px of where it was |
