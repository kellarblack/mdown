# The hero lockup, rebuilt on one number

The type size is now the only measurement in the lockup. The mark, the gap, the
tracking and the entrance are all fractions of it, so the ratio can't drift
between 320px and 1440px. That is the whole change.

---

## 1 · Markup — replace the `<h1 class="hero-logo">` block in `index.html`

Inside `<div class="hero">`, replace the whole `<h1 class="hero-logo">…</h1>`
block with this:

```html
    <h1 class="hero-logo">
      <span class="hero-mark" aria-hidden="true">
        <svg viewBox="1 1 30 30" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
          <!-- the arrow is its own group so it can travel into the tray: the
               mark reads as something being downloaded, not as a shape fading.
               Drawn on a 30-unit grid whose ink fills it edge to edge, which
               is why the viewBox starts at 1 instead of 0. -->
          <g class="mark-arrow"><path d="M16 2v17"/><path d="m10.5 13.5 5.5 5.5 5.5-5.5"/></g>
          <path d="M2 20v7a3 3 0 0 0 3 3h22a3 3 0 0 0 3-3v-7"/>
        </svg>
      </span>
      <span class="hero-word">m<span class="hero-word-down">down</span><span class="hero-word-dot">.</span><span class="hero-word-tld">cc</span></span>
      <span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

What changed in it: the mark is redrawn (a real cup with a 3-unit corner radius
instead of a single underline at the bottom), `m` no longer needs its own span,
`cc` is renamed `.hero-word-tld`, the unused `.hero-type` wrapper and the
unused `.mark-tray` class are gone, and the `<span class="sr-only">` line is
untouched. `<h1>`, the real text, and `aria-hidden` on the mark all stay. No
other file refers to the old class names — `app.js` never touches the lockup —
so renaming `cc` costs nothing.

## 2 · CSS — replace this block in `assets/app.css`

Delete everything from the comment `/* one flow: the arrow rises, the name
follows it… */` down to `.hero-logo { margin-bottom: clamp(18px, 3vh, 28px); }`
— that is every rule named `.hero-logo`, `.hero-mark`, `.hero-mark svg`,
`.mark-arrow`, `.hero-word`, `.hero-type`, `.hero-word-m`, `.hero-word-down`,
`.hero-word-dot`, `.hero-word-sub`, plus `@keyframes hero-fade-in`,
`arrow-drop` and `word-drop` and the reduced-motion block inside it — and put
this in its place:

```css
/* ---------- hero lockup ----------
   One object, one em. The lockup sets its own type size here and every other
   number in this block is a fraction of it, so the mark, the gap and the
   tracking scale together at every width: there is no second clamp to keep in
   sync and nothing to re-tune at a breakpoint.
   The row aligns on the baseline, so the mark and the letters stand on the
   same line instead of being centred against each other. */
.hero-logo {
  display: flex; align-items: baseline; justify-content: center;
  gap: 0.3em;
  margin: 0 auto clamp(18px, 3vh, 28px);
  font-family: var(--mono);
  font-size: clamp(1.75rem, 4.2vw, 2.4rem);
  line-height: 1;            /* the lockup is exactly as tall as its type */
  color: var(--text);
}

/* The mark is three quarters of the type size and its foot sits on the
   baseline, so it fills the band the letters are drawn in — baseline up to
   ascenders. The artwork is drawn flush to the edges of its box (the viewBox
   *is* the ink box), so 0.75em is 0.75em of drawing, not of drawing plus
   padding. Stroke 2 on a 30-unit grid renders ~1.9px at the default size and
   keeps its proportion as the type shrinks, the way letter stems do. */
.hero-mark {
  flex: none;
  width: 0.75em; height: 0.75em;
}
.hero-mark svg {
  display: block; width: 100%; height: 100%;
  /* the arrow starts just above the box: without this the svg viewport cuts
     its top off. It paints inside the h1's own line box, never outside the
     lockup, and only while the entrance runs. */
  overflow: visible;
}

.hero-word {
  font-weight: 500;
  letter-spacing: -0.02em;   /* the same tracking .brand-text uses in the topbar */
  white-space: nowrap;       /* the lockup is one line at every width */
}
.hero-word-down { display: inline-block; }  /* only so it can carry a transform */
/* The dot is the accent, so the period is the one mark of colour on the page.
   In a monospaced cell the period does not sit centred: on SF Mono the gap it
   leaves is 0.28em on the left against 0.34em on the right, so the gap before
   a dot is already tighter than the gap after one. This gives back the 0.06em
   difference and nothing else, leaving 0.26em either side once the -0.02em
   tracking is counted. */
.hero-word-dot { color: var(--accent); margin-right: -0.06em; }
/* the tld belongs to the name, not to a footnote: same size, same tracking,
   one step down in tone — the way .brand-sub sets it in the topbar */
.hero-word-tld { color: var(--text-3); }

/* Entrance: the arrow falls into the tray and "down" falls with it. The same
   distance each (0.075em: 3 of the mark's 30 units is a tenth of its three
   quarters), the same curve, the same 760ms, the word 60ms behind so it
   follows the arrow rather than moving with it. Transform only, so nothing
   reflows and no text repaints; and the travel is shorter than the air the
   line already has above its ink, so the gesture cannot leave the h1's box or
   be cut off by anything. */
.hero-logo { --hero-drop: 760ms; }
.mark-arrow { animation: hero-arrow var(--hero-drop) var(--ease) both; }
@keyframes hero-arrow {
  from { transform: translateY(-3px); }   /* 3 of 30 units = 0.075em */
  to   { transform: translateY(0); }
}
.hero-word-down { animation: hero-word var(--hero-drop) var(--ease) 60ms both; }
@keyframes hero-word {
  from { transform: translateY(-0.075em); }
  to   { transform: translateY(0); }
}
@media (prefers-reduced-motion: reduce) {
  .mark-arrow, .hero-word-down { animation: none; }
}
```

Leave `.hero { width: 100%; }` above it, and leave the landscape rule further
down (`.hero-logo { display: none }` at the orientation query) exactly as it is.

### The numbers those come from

| | 1440px (type 38.4px) | 320px (type 28px) |
| --- | --- | --- |
| mark | 28.8px square, stroke 1.9px | 21px square, stroke 1.4px |
| gap | 11.5px | 8.4px |
| wordmark, 8 mono cells | ≈177px | ≈129px |
| lockup | ≈217 × 38.4px | ≈158px wide, of 288px available |

## 3 · Why this, not the old one

The old lockup was two objects arguing. The mark was clamped 34–44px while the
type was clamped separately, so their ratio changed at every width; its 2-stroke
arrow scaled up past 3px next to 1.1px icons in the topbar; and the tray was a
lone underline 4 units below the arrow, so the mark never closed. It also sat
centred against the word rather than standing on its line, and the `0.05em` on
`down` was there to stop it hitting the `m` — a collision that can't happen,
since the letters only move vertically. That margin just made the monospaced
spacing uneven forever. `cc` was set smaller *and* dimmer *and* with a `2px`
margin, three fixes for one word. Now: one size, one band, one tonal step, and
the period alone carries the accent.

## 4 · Check it

At **1440px**: the mark's foot is level with the bottom of the `m` and its top
level with the top of the `d`; the period's air is equal on both sides; on
reload, the arrow lands in the tray and `down` lands with it, once, quietly.

At **360px** (and 320px): still one line, ~158px wide and centred — same
proportions, nothing wraps, nothing touches the composer above or below.

## Notes

- **One knock-on, unavoidable:** the lockup is now 38.4px tall instead of 44px
  (the old 44px mark set the row's height). Because `#download-view` centres
  its column, the composer settles about 3px lower. Nothing else on the page is
  touched.
- **Reduced motion** is handled twice: the local `animation: none` above, and
  the page-wide duration override already in the file.
- **The old arrow was being clipped.** Its `translate3d(0, -9px, 0)` start put
  the arrow's top outside the `0 0 24 24` viewBox, which clips by default — the
  240ms fade over the whole lockup was disguising it. `overflow: visible` plus
  a travel that fits inside the line box removes both problems.
- **If you ever want a bigger drop, the ceiling is 0.085em.** Past that the `d`
  starts above the h1's line box, which is the thing that keeps this gesture
  from touching the page. It currently uses 0.075em, so there is 0.01em in hand.
- **Assumptions:** `--accent` is `#ededee` in dark mode, so the dot reads as
  full-strength ink while `cc` steps down to `--text-3`; I kept `var(--accent)`
  so it follows the theme if that ever changes. I kept the arrow-into-tray
  concept — the complaint was that the lockup doesn't look designed, not that
  the idea was wrong. "Level with the ascenders" is measured on SF Mono (the
  first font in the stack); on Menlo or Consolas the ascender differs by a few
  hundredths of an em and the mark simply sits a hair proud of it.
