# The hero lockup: one line, one scale

## What is actually wrong with it

Four separate things, all measurable in the two files:

1. **The mark is the 15px top-bar icon, scaled up 3×.** `index.html:192` draws the same arrow
   and tray in the same 24-unit box at 15px, where the 2-unit stroke lands at 1.25px. The hero
   draws it at 44px, so the same stroke lands at **3.67px** — the icon's hairlines get 3× fatter
   as the logo gets bigger. That is the single biggest reason it reads as a website icon rather
   than a logo.
2. **The drawing is square, so it cannot sit inside a word.** Its ink is 16×16 units in a 24 box:
   at cap height it would be 28px wide where the m's ink is 19px. A mark that is one and a half
   letters wide is a badge next to the word, not a glyph in it.
3. **The lockup is two scales plus a constant.** Mark = `clamp(34px, 5vw, 44px)`, word =
   `clamp(1.75rem, 4.2vw, 2.4rem)`, gap = a flat `14px`. So the gap is 0.69 of the cap on a
   320px phone and 0.50 on a 1440px desktop — the mark-to-word air is 38% looser on a phone,
   and the mark's ink runs 1.25× the cap there against 1.18× on the desktop.
4. **The word is split so half of it can move, and the seam is patched.** `.hero-word-down` gets
   `margin-left: .05em` to stop the seam showing while it falls. In a monospace wordmark — a
   typeface that is *only* rhythm — the m-to-d gap is then different from every other pair, and
   that stays after the animation lands. The tail is over-corrected the same way: `0.72em`,
   weight `400`, `--text-3`, `letter-spacing: 0` and a `2px` nudge, five changes at once, which
   is why it reads as leftovers rather than as the same wordmark set smaller. (Also: the dot's
   `--accent` is `#ededee` in dark and `#121213` in light — identical to `--text` in both
   themes, so the "accent dot" had no accent to give.)

The fix is not a new idea, a tagline or a spotlight. It is putting every part of the lockup on
the type's own measurements, and letting the type be one text run again.

---

## 1 · `index.html` — replace the `<h1 class="hero-logo">` block (the one above the composer)

```html
    <h1 class="hero-logo">
      <span class="hero-mark" aria-hidden="true">
        <svg viewBox="0 0 14.4 28" fill="none" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round">
          <!-- the arrow is its own group so it can travel into the tray: the
               mark reads as something being downloaded, not as a shape fading -->
          <g class="mark-arrow"><path d="M7.2 8.6v16.6"/><path d="m2.2 20.2 5 5 5-5"/></g>
          <path class="mark-tray" d="M0 28h14.4"/>
        </svg>
      </span>
      <span class="hero-word">mdown<span class="hero-word-dot">.</span><span class="hero-word-sub">cc</span></span>
      <span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

What changed: the mark is redrawn on a 14.4 × 28 grid (the cap is 20 units, the tray sits on
unit 28, the extra 8 units at the top are head-room for the drop), and the word is one text run
again. `.hero-type`, `.hero-word-m` and `.hero-word-down` are gone; the `<h1>`, the real text,
the `aria-hidden` mark and the `.sr-only` line stay.

## 2 · `assets/app.css` — replace this block

**Delete** the block that starts at the comment `/* one flow: the arrow rises, the name follows
it, the line follows the name.` and ends at `.hero-logo { margin-bottom: clamp(18px, 3vh, 28px); }`
(the block of hero rules the brief quotes, around lines 2270–2340). That block is: `.hero`,
`.hero-logo`, `.hero-mark`, `.hero-mark svg`, `.hero-logo` again, `@keyframes hero-fade-in`,
`.mark-arrow`, `@keyframes arrow-drop`, `.hero-word-down`, `@keyframes word-drop`, `.hero-word`,
`.hero-type`, `.hero-word-m`, `.hero-word-down` again, the `prefers-reduced-motion` block,
`.hero-word-dot`, `.hero-word-sub`, and the second `.hero-logo`. Paste this in its place:

```css
.hero { width: 100%; }

/* One line of type and one mark, built on the same two rules: the tray is the
   text baseline, the arrow is the cap height. Every size below is em or cap, so
   the whole lockup scales from the one font-size here — the mark and the gap can
   no longer drift away from the word as the viewport changes. */
.hero-logo {
  display: flex; align-items: baseline; justify-content: center;
  gap: .28em;
  margin: 0 auto clamp(18px, 3vh, 28px);
  font-family: var(--mono);
  font-size: clamp(1.75rem, 4.2vw, 2.4rem);
  font-weight: 500; line-height: 1; letter-spacing: -.03em;
  color: var(--text);
}

/* The mark is drawn on a 20-unit cap inside a 28-unit box: the spare 8 units at
   the top are head-room, so the arrow has somewhere to fall from and the drop
   never leaves the lockup or gets clipped. Box = 1.4 × cap. Width = .72 × cap,
   about the ink width of one mono letter at this size. `cap` is the real cap
   height of whichever mono the platform gives us; the em line above it is the
   fallback and keeps the same ratios, so nothing shifts if `cap` is unsupported. */
.hero-mark {
  display: flex; flex: none;
  height: 1.01em; height: 1.4cap;
  width: .52em; width: .72cap;
  color: var(--text);
}
.hero-mark svg { display: block; width: 100%; height: 100%; overflow: visible; }

.hero-word { display: block; white-space: nowrap; }

/* In mono the full stop sits in a .6em cell with its ink left of centre, so even
   at .6em it renders as a hole: 0.23em of air on the n side, 0.29em on the c
   side, against the 0.02–0.13em the letters leave each other. Pulling .14em off
   each side brings it to 0.09em from the n and about 0.14em from the c, which is
   what lets it read as the full stop of the name — and as the one full-strength
   mark in the tail. */
.hero-word-dot { color: var(--accent); margin: 0 -.14em; }

/* the domain: one step down in size, one step quieter in tone — and the name's
   weight and tracking kept, so the suffix is the same wordmark set smaller
   instead of a second treatment bolted on the end */
.hero-word-sub { font-size: .8em; color: var(--text-2); }

/* One gesture: the arrow drops into the tray and stops. Nothing else moves — no
   fade on the name, no second beat, no overshoot — and the tray itself never
   moves, so the line the lockup is built on holds for the whole 620ms. Four
   units of the mark's own 20-unit cap is 5.6px at the desktop size and 4.1px on
   a 320px phone: proportional by construction. */
.hero-mark .mark-arrow { animation: arrow-drop 620ms var(--ease) both; }
@keyframes arrow-drop {
  from { transform: translate3d(0, -4px, 0); }
  to   { transform: translate3d(0, 0, 0); }
}

/* nobody asked for motion: show the mark landed and be done */
@media (prefers-reduced-motion: reduce) {
  .hero-mark .mark-arrow { animation: none; }
}
```

Nothing else in either file has to change: no new tokens, no new colour, no JS, no media query.
The landscape-phone rule — `@media (orientation: landscape) and (max-height: 500px) and
(max-width: 1024px) { .hero-logo { display: none; } }` — still comes later in the file and still
wins, so the lockup stays hidden on a phone on its side.

One housekeeping step: bump the stylesheet's cache-buster in `index.html`
(`assets/app.css?v=273` → `?v=274`), or your browser will serve the old hero from cache and you
will think nothing happened.

## 3 · Why this, not the old one

The old hero was a 15px icon scaled to 44px beside a word on another clamp, with a fixed 14px
gap: the icon's hairlines arrived three times too fat, the mark was a square block one and a
half letters wide, and the air between mark and word changed by a third from phone to desktop.
There is no second scale now. The mark is exactly cap height and one letter wide, its tray *is*
the baseline, and the gap, the suffix and the drop are all in em, so the lockup measures the same
at 320px and 1440px. The word is one text run again, which removes the 0.05em seam patch that
made the m-to-d gap uneven in a typeface whose only job is even spacing. The arrow is the only
thing that moves — the one part of the old entrance that described something real.

## 4 · Three trade-offs, stated plainly

- **The second half of the name no longer falls.** That was the part of the old gesture that
  was liked, and it is the part I am giving up. It cannot survive the fix: the split is what
  forced the seam patch, a half-word dropping is the beginning of the per-letter choreography
  that was rejected as amateur, and a word moving down would break the baseline the lockup is
  now built on for half a second. What is left is smaller and quieter: the arrow lands.
- **The mark is lighter than the type.** Its stroke measures about 0.6 × the wordmark's stem
  (2.1px against 3.5px at 38px type here), which is what makes it read as a hairline mark
  instead of a bold icon. The cost: on a 1× non-retina screen at 320px that hairline is 1.5px
  and a little faint. The alternative is the heavy version being replaced.
- **This is a hero drawing, not the 15px one.** Same three strokes, tighter gap and narrower
  tray, because a square icon cannot become a letter. If you would rather have one drawing
  everywhere, keep the old 24-unit paths and take only the sizing and typography rules — it
  will look looser at hero size, which is the problem you started with.

## 5 · Check it

**At 1440px:** the tray is the same line as the bottom of "mdown.cc", the arrow's tip reaches
the cap line, the full stop sits tight to the n (0.09em) with a period's worth of air before the
cc (0.14em), and the whole lockup is 187px wide over the 848px composer.

**At 360px:** nothing wraps or clips (the lockup is 138px wide, still centred), the mark stays
a hairline, and "cc" at 22.4px in `--text-2` is still 7.7:1 against the page.

Numbers, measured in Chrome at 1440px with the old block and the new one:

| | old | new |
| --- | --- | --- |
| mark ink height | 33px (1.18 × cap) | 28px (1.00 × cap) |
| mark ink width | 29.3px (1.5 × the m's ink) | 20.1px (1.05 × the m's ink) |
| mark stroke | 3.67px | 2.1px |
| gap, in cap heights | 0.69 at 320px → 0.50 at 1440px | 0.38 at every width |
| tray vs baseline | ≈0.4px above (coincidence) | 0.00px (checked) |
| "cc" | 0.72em, 400, `--text-3`, tracking reset, +2px | 0.8em, 500, `--text-2`, name's tracking |
| composer top (side effect) | — | +0.8px at 1440px, −0.1px at 768px |

Also checked: no horizontal overflow at 320/360/390/768/1024/1440; under
`prefers-reduced-motion: reduce` the arrow's `animation-name` computes to `none` and the mark
renders landed; at 844 × 390 (a phone on its side) `.hero-logo` still computes to `display: none`
while a 1440 × 400 window keeps it.

## 6 · Assumptions

- The inline `<svg>` stays in the markup — the brief rules out SVG *files*, and the hero already
  ships an inline one.
- `cap` is supported in Safari 16.4+, Chrome 99+ and Firefox 97+; older browsers fall through to
  the `em` values, which keep 0.72/1.4 = 14.4/28 — the same proportion, so the lockup does not
  move.
- "Nothing else on the page changes" is taken to mean no other component is redesigned. The
  lockup's own box does get 1.6px taller, because the mark's head-room is now part of its box;
  the measured effect on the composer is under a pixel in either direction.
- Every number above was measured in Chrome on macOS, where the mono resolves to Menlo
  (cap 0.729em, stems 0.09em). Real SF Mono is 0.73 cap, Consolas 0.64 — which is exactly why
  the mark and the gap are in `cap` and `em` rather than pixels: they follow whatever the
  platform calls a cap height instead of trusting this screenshot.
