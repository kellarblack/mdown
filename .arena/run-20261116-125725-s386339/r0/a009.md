# The hero lockup: one scale, one baseline

Two blocks to swap: the `<h1 class="hero-logo">` in `index.html`, and the hero block in
`assets/app.css`. Nothing else changes.

## 1. `index.html` — replace the `<h1 class="hero-logo">` block

```html
    <h1 class="hero-logo">
      <span class="hero-mark" aria-hidden="true">
        <!-- the arrow is its own group so it can land in the tray; the 3 units of
             empty height at the top of the box are its runway -->
        <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2.5" stroke-linecap="round" stroke-linejoin="round">
          <g class="mark-arrow"><path d="M12 4.25V16"/><path d="M6.4 10.4l5.6 5.6 5.6-5.6"/></g>
          <path class="mark-tray" d="M1.25 18.75v4h21.5v-4"/>
        </svg>
      </span><span class="hero-word">mdown<span class="hero-word-dot">.</span><span class="hero-word-sub">cc</span></span><span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

## 2. `assets/app.css` — replace the hero block

The block starts at `.hero { width: 100%; }` and ends at the single
`.hero-logo { margin-bottom: clamp(18px, 3vh, 28px); }` line just above `.meta-line {`.
Go by those two anchors rather than by line numbers — this file has been moving. The block
holds `.hero`, `.hero-logo` (twice), `.hero-mark`, `.hero-mark svg`, `.hero-word`,
`.hero-type`, `.hero-word-m`, `.hero-word-down`, `.hero-word-dot`, `.hero-word-sub`,
`.mark-arrow`, the keyframes `hero-fade-in`, `arrow-drop` and `word-drop`, and the
`prefers-reduced-motion` block. Replace all of it with:

```css
.hero { width: 100%; }

/* ---------- the lockup: one scale, one baseline ----------
   One type size drives the mark, the gap and the name, so the proportions are
   the same at 320px and at 1440px. Nothing in here is a fixed pixel. */
.hero-logo {
  --logo: clamp(1.75rem, 4.2vw, 2.4rem);   /* your ramp, unchanged */
  /* the old mark's 34–44px box set the hero's height; holding that footprint
     keeps the composer exactly where it is now */
  min-height: clamp(34px, 5vw, 44px);
  display: flex; align-items: baseline; justify-content: center;
  gap: 0.22em;
  margin: 0 auto clamp(18px, 3vh, 28px);
  font-size: var(--logo);
  color: var(--text);
}

/* The mark is 0.86em square and its box *is* the drawing: no dead sidebearings,
   so the gap you see is the gap that is there. Baseline alignment does the
   vertical work — a replaced inline sits its bottom edge on the baseline, so the
   tray lands on the same line as the feet of the letters with no offset. The
   drawing is 0.75em tall: the band from the baseline to the top of the "d"
   (0.76em). The empty 0.11em at the top of the box is the arrow's runway. */
.hero-mark { display: inline-block; flex: none; line-height: 0; }
.hero-mark svg { display: inline; vertical-align: baseline; width: 0.86em; height: 0.86em; }

/* A monospace name already carries its spacing: -0.03em was shutting the
   counters. Back to 0, and the string stops wrapping. */
.hero-word {
  font-family: var(--mono); font-weight: 500;
  font-size: 1em; line-height: 1; letter-spacing: 0;
  white-space: nowrap;
}
/* The period belongs to the suffix, not to the name: at the suffix's size it is
   a period — at 38px this mono's period ink is a 6.6 x 7.6px block that
   out-weighs the cc. Its cell still needs pulling in, because a mono period sits
   centred in a whole 0.6em cell. Em-based, so it holds at every size. */
.hero-word-dot { color: var(--accent); font-size: 0.7em; margin-inline: -0.06em; }
/* The tld: one step smaller, one step greyer, tracked open — smaller letters
   need more air than large ones to keep the same texture as the name. */
.hero-word-sub {
  font-size: 0.7em; font-weight: 400; color: var(--text-2);
  letter-spacing: 0.035em; margin-left: 0.06em;
}

/* One gesture, one curve, one duration, no delay: the lockup comes up to full
   ink while the arrow lands in the tray. The name itself does not move — the
   shared baseline is the whole point — and the arrow starts exactly at the top
   edge of its own box, so nothing leaves the lockup and nothing is clipped.
   Transform and opacity only. */
.hero-logo { animation: hero-ink 620ms var(--ease) both; }
.mark-arrow { animation: arrow-seat 620ms var(--ease) both; }

@keyframes hero-ink { from { opacity: 0; } to { opacity: 1; } }
@keyframes arrow-seat {
  from { transform: translateY(-3px); }   /* 3 of the mark's 24 units */
  to   { transform: translateY(0); }
}

@media (prefers-reduced-motion: reduce) {
  .hero-logo, .mark-arrow { animation: none; }
}
```

Two rules outside this range still apply and are correct as they are: `.hero-logo { display:
none }` in the landscape-phone query, and `.hero { padding-top: 2vh … }` in the `max-height:
700px` query.

## Why this, not the old one

The old lockup was two objects. The mark had its own clamp (34–44px), the name scaled on
another curve, the drawing sat in a box with 3 units of dead space at each edge, and the gap
was a flat 14px: the space between the arrow and the `m` was 21px on desktop and 20px at
320px while the type shrank from 38.4 to 28px. No proportion, and nothing tying the two
halves to one line.

Now one type size drives all of it: mark 0.86em square, strokes 0.09em (the mono's own stem),
gap 0.22em, and the drawing exactly the baseline-to-ascender band — so the tray stands on
the line the letters stand on.

The entrance is one curve, not three beats. Dropping half the name split `mdown` in two for
most of a second; now the mark lands on its own.

## Check it

- **At 1440px:** the tray's floor should read level with the feet of the letters and the
  top of the arrow level with the top of the `d`; the arrow should clear the tray's floor by about a
  fifth of the mark's height; the gap to the `m` should feel like one space, not a slot; the `cc`
  should step back without going mute.
- **At 360px:** the same relationships, on one line, nothing wrapped or clipped — drag the
  window slowly from 1440 to 320 and the ratio between mark, gap and name should not change at
  all.

## Notes

- **Three dials.** `gap: 0.22em` to move the mark and the name apart or together, `0.86em` for
  the mark's box, and `stroke-width="2.5"` (of the viewBox's 24 units) for its weight. Change
  one and nothing else moves.
- **The dot** takes `--accent`. Today that resolves to the same ink as `--text`, so it reads as
  the period of the word; if you ever give `--accent` a hue, the dot follows and nothing else
  does.
- **Measured** in Chrome 157 after the swap: the tray's floor to the text baseline is 0.00px at
  1440, 900, 360 and 320; the arrow's start position is exactly the top edge of its own box (no
  clipping); no horizontal overflow at 320; and the composer's top is unchanged at every width.
- **The name is one ink** again: greying `down` split the word into a white `m` and a grey tail —
  the same split the word-fall made, so it goes with it.
- **The tray** gets 4 units of wall (of 24). A bare rule under an arrow is an underscore at hero
  size; the walls are the smallest change that makes it read as a tray at 19px too.
- **The topbar mark** is left alone: out of scope, and at 15px the tray's 4-unit walls would be
  sub-pixel.

## Assumptions

- `cc` is a domain suffix, not a second word: one step smaller and greyer, on the same baseline.
- The `m`/`down` spans are gone because nothing animates half the word any more. The `<h1>` still
  contains the same text, the mark is still `aria-hidden`, and the visually-hidden description is
  untouched — the accessible name is still `mdown.cc — a media downloader for video and audio`.
