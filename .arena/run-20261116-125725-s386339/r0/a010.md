# The hero lockup: one object, sized from one number

Mark and wordmark come from a single em: the mark's ink is exactly the cap height of the word and sits on
its baseline, the gap is 0.21em, and the entry is the paired drop you already liked — arrow into the tray,
name settling with it, nothing split, nothing bouncing. Numbers below were measured from renders at
320–1440px, not estimated.

**Assumptions** (three, so nothing is ambiguous):

- The lockup keeps its place, container and bottom margin; only the `<h1>` markup and the hero CSS change.
- `--accent` equals `--text` in both themes, so the dot's job is full-strength ink against a `--text-3`
  `cc`. I kept that relationship instead of introducing a colour.
- The paired drop is kept, but the pair is now the mark and the *whole* name. Splitting the name after the
  `m` is the one liked detail I removed on purpose — the reason is under "Why this".

## 1. HTML — replace `index.html` lines 305–316

The whole `<h1 class="hero-logo">…</h1>`, from `<h1` through `</h1>`. The `<div class="hero">` above it
and `<section class="composer">` below it stay exactly as they are.

```html
    <h1 class="hero-logo">
      <svg class="hero-mark" viewBox="0 0 20 20" fill="none" stroke="currentColor" stroke-width="2.5"
           stroke-linecap="round" stroke-linejoin="round" aria-hidden="true" focusable="false">
        <!-- the arrow travels; the tray is the resting line it lands on -->
        <path class="mark-arrow" d="M10 1.25V10.15"/>
        <path class="mark-arrow" d="m6.2 6.35 3.8 3.8 3.8-3.8"/>
        <path d="M1.25 13.85V17.2a1.55 1.55 0 0 0 1.55 1.55h14.4a1.55 1.55 0 0 0 1.55-1.55V13.85"/>
      </svg>
      <span class="hero-word">mdown<span class="hero-word-dot">.</span><span class="hero-word-sub">cc</span></span>
      <span class="sr-only"> — a media downloader for video and audio</span>
    </h1>
```

What moved: `.hero-mark` is now the `<svg>` itself (the wrapper span is gone), and the `.hero-type` /
`.hero-word-m` wrappers are gone. The `<h1>` stays, the wordmark stays real text, the mark is still
`aria-hidden`, and the `<h1>`'s accessible name is unchanged.

## 2. CSS — replace `assets/app.css` lines 2301–2369

That range runs from `.hero { width: 100%; }` down to the last `.hero-logo { margin-bottom: … }`, and it
includes the rules `.hero-mark`, `.hero-mark svg`, `.hero-word`, `.hero-type`, `.hero-word-m`,
`.hero-word-down`, `.hero-word-dot`, `.hero-word-sub`, `.mark-arrow`, `@keyframes hero-fade-in`,
`@keyframes arrow-drop`, `@keyframes word-drop` and the old reduced-motion block. Delete all of it, then:

```css
/* ---------- hero lockup ---------- */
.hero { width: 100%; }
.hero-logo {
  /* one number sizes the whole lockup: mark box, wordmark, gap and drop are
     all em, so nothing can drift apart between 320px and 1440px */
  font-size: clamp(2.125rem, 1.15rem + 2.45vw, 3rem);   /* 34px → 48px */
  display: flex;
  align-items: baseline;      /* the mark's ink sits on the name's baseline */
  justify-content: center;
  gap: 0.16em;                /* 8px between the boxes at 1440, 10px of air
                                 between the inks: wider than any gap inside the
                                 name, so it stays two objects and one lockup */
  margin: 0 auto clamp(18px, 3vh, 28px);
  color: var(--text);
  animation: hero-in 380ms var(--ease) both;
}

.hero-mark {
  flex: none;
  display: block;
  /* 0.73em is the cap height of the wordmark at every size, so the mark is
     exactly one cap tall and its ink runs baseline to cap line */
  width: 0.73em;
  height: 0.73em;
  /* the arrow's first frame is above the box: nothing may clip it */
  overflow: visible;
}

.hero-word {
  /* inline-flex, not inline-block: whitespace between the spans is ignored, so
     a reformat of the markup cannot open a gap inside the name. It also gives
     transform a box to move — transforms do nothing on an inline box. */
  display: inline-flex;
  align-items: baseline;
  font-family: var(--mono);
  font-weight: 500;
  font-size: 1em;
  line-height: 1;
  letter-spacing: -0.015em;   /* mono is loose at display size; 1.5% is enough */
  white-space: nowrap;
  animation: hero-word-in 760ms var(--ease) both;
}

/* the period is one 0.602em mono cell with 0.19em of bearing on its left and
   0.24em on its right. Pulling 0.155em / 0.22em off leaves 5px and 4.5px of
   air at 1440px: a full stop that was placed, not a gap that happened. */
.hero-word-dot { color: var(--accent); margin: 0 -0.22em 0 -0.155em; }

/* the tld at the same size, one step down in value — the move the top bar
   already makes with .brand-sub, so hero and header are the same mark */
.hero-word-sub { color: var(--text-3); }

/* one paired move, no stagger, no bounce: the arrow drops into the tray while
   the name settles with it, same curve, same 760ms. The name is never split,
   so no seam can open inside it. Transform and opacity only, and it ends on
   the layout it started on. */
@keyframes hero-in { from { opacity: 0.6; } to { opacity: 1; } }
@keyframes hero-word-in { from { transform: translateY(-0.06em); } to { transform: translateY(0); } }
@keyframes arrow-in { from { transform: translateY(-4px); } to { transform: translateY(0); } }
/* -4px is 4 of the mark's 20 grid units (0.2 x the mark): 7px at 1440, 5px at
   360 — the drop scales with the lockup instead of shrinking into a nudge */
.mark-arrow { animation: arrow-in 760ms var(--ease) both; }

@media (prefers-reduced-motion: reduce) {
  .hero-logo, .hero-word, .mark-arrow { animation: none; }
}
```

## Why this, not the old one

The old lockup was two objects with a gap. Its mark's ink stopped 21px (0.55em) short of the `m`, where
the widest gap inside the word is 7px — so the arrow read as an icon parked on the left. Its period sat
3.7px from the `n` and 7.0px from the `cc`, which makes one side look glued and the other adrift. The `cc`
was 72% size with a fixed 2px nudge that never scaled. And `down` split off the `m` for 760ms: a 5.4px
step inside a 21px x-height reads as a typo, not a gesture.

Here the mark is one cap tall on the name's baseline, same stroke weight, at one em-derived distance; the
period is kerfed from both sides; `cc` is full size, one value step down; and the name never breaks.

The numbers, old → new (old ran at 38.4px, new at 48px; the em figures are comparable):

| | old | new |
| --- | --- | --- |
| mark ink height vs cap height | 29.3 / 28.0px | 35.0 / 35.0px |
| gap mark → `m` | 21px (0.55em) | 10px (0.21em) |
| period gaps, left / right | 3.7 / 7.0px | 5.0 / 4.5px |
| `cc` | 0.72em, fixed 2px offset | 1em, one value step |
| name during entry | splits after `m` by 5.4px | never splits |

## Verification

**1440px:** the tray's bottom sits level with the feet of `mdown` while the arrow's head meets the cap
line, and the gap to the `m` is 10px — wider than any gap inside the name, well under half a letter cell
(29px) — so mark and name read in one glance, with `cc` a step lighter at the same size.

**360px:** the same at 34px — centred, one line, nothing clipped; rotate the phone to landscape (844×390)
and the lockup disappears, exactly as it does now.

## Four things that can go wrong on paste

1. **Order matters.** Keep the block where the old one was (above the landscape media query at ~line 3155
   that sets `.hero-logo { display: none; }`). Pasted at the end of the file it wins on source order and
   the lockup comes back on landscape phones.
2. **Check the delete was complete.** `grep -n "hero-" assets/app.css` should now return only `.hero {`,
   `.hero-logo {`, `.hero-mark {`, `.hero-word {`, `.hero-word-dot`, `.hero-word-sub`, `.mark-arrow` and
   the landscape `.hero-logo`. Any hit on `hero-word-down`, `hero-type` or `hero-word-m` means the old
   block is still in there, and its `0.72em` on `.hero-word-sub` will quietly shrink `cc` again.
3. **Do not drop `overflow: visible` on `.hero-mark`.** The arrow's first frame is 4 units above the svg
   box; without it the drop is clipped for the first ~200ms.
4. **Reduced motion** (System Settings → Accessibility → Display → Reduce motion): the lockup should
   appear already settled — no movement, nothing offset, nothing clipped. In a substituted mono (Consolas,
   Liberation Mono) the period may sit ~1px off-centre; fix it by taking 0.01em off one of the two
   `.hero-word-dot` values and adding it to the other, which slides the period without changing its gaps.
