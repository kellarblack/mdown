Plain language, no lawyer cosplay. Using mdown means accepting everything below.

01What mdown is

mdown is a page and an API. The page is static: paste a link and it asks an API server to do the work, then hands you the file. You do not have to use this one. Point Settings → Server at your own copy and the downloads run through your machine instead. It is open source under the MIT licence at github.com/kelllar/mdown; read it, fork it, run it. The server writes each finished file to disk, hands it over once, and deletes it within fifteen minutes. It keeps no library and redistributes nothing.

Service names are used to describe technical compatibility only. There is no affiliation with, endorsement by, or partnership with any service listed, and none is implied.

  • Abuse the server. Automated scraping, resale of access, or anything that gets the host terminated.

04The API

mdown.cc talks to one server, and that server is sized for this page. It checks where requests come from, rate-limits by address, and has a finite daily budget. Pointing another app, bot or reseller at it is not permitted and will be blocked without notice.

The full policy, with the numbers, is at api.html (also as a pdf).

The protocol is open and the server code is in the same MIT repository. If you need an API, run your own. That is the intended path, and a small vps is enough.

06Privacy

Settings and recent links live in your browser's local storage. No account, no cookies, no analytics. Requests for links and files go to the server in Settings. Thumbnails are loaded from the source itself, so that host sees your address; nothing else does. Files processed by the local tools never leave your device, and files downloaded through an API are deleted shortly after they are handed over.

The server keeps no record of what was downloaded. There is no history and no per-user record: the link is held in memory while the job runs and is not written to a log or a database. A tunnel address is stored as /tunnel/[redacted] in the server log, query strings are dropped, and links that a tool prints are replaced before they are logged. The web server's access log drops the address of the visitor, the browser, the referer and cookies. The page, the API and the file travel over TLS.

The finished file is not encrypted on the server's disk while it waits, because the server has to read it to send it. Someone with root access to the machine could watch a download while it is in flight or read that temporary file before it is deleted. That is the limit of a server-side downloader. What this server does not do is keep anything afterwards.
